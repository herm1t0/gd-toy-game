# The simulation is a pure C# core; Godot owns movement and presentation

Match state (#10) lives in a `ToyGame.Sim` assembly that does **not** reference `GodotSharp`: unit roster and stats, targeting, the 0.25 s engagement tick, the **Fight slot** registry, damage rolls and the match-seeded RNG, projectile landing resolution, gold and income, the **Build slot**, **Upgrade levels**, **Research** flags, the **Spawn queue**, the **Army cap**, **Base** HP, win/lose and the AI's decisions. Godot nodes own only transform, `NavigationAgent3D` and avoidance, animation, audio, decals, health bars, camera and UI. Each physics frame the node writes its position into the sim, the sim steps, and the sim writes one intent per unit back (`Kind` / `GoalPoint` / `StopDistance`).

The split is drawn at movement because movement is the one system where the engine's stack is already the answer: #3 found `NavigationAgent3D` + 2D avoidance + `MoveAndSlide()` adequate at this scale, and its risks are engine internals. Reimplementing avoidance in the sim would trade a weekend for determinism nobody asked for. Everything else is game logic, and game logic that lives in the scene tree can only be tested with the engine — which #2 found runs through GdUnit4, a package whose compatibility matrix does not list 4.8. The absence of a Godot reference *is* the enforcement: a leak from view code into the sim becomes a compile error.

**Considered options:** nodes own everything, with pure C# only for stat tables and damage math (engine-coupled logic, and the tick, targeting and slot registry — the actual design risk per #3 — become untestable without a running match); a fully pure C# simulation including custom steering and RVO (total testability, no engine dependency for movement, but it discards #3's recommended stack and re-implements the hardest engine feature); custom `Resource` definitions consumed by the sim (editor-tweakable, but either the sim takes a Godot dependency or every match start copies `.tres` into sim records through a conversion layer).

**Consequences:** a seed reproduces every roll, damage number and decision but **not positions**, because avoidance runs in the engine's thread pool — so reproducibility is proven by a state-hash test on the sim, not by replaying a whole match; logging node positions per tick in debug builds is the fallback if a micro-movement bug ever needs replaying. The slice ships three projects (`ToyGame`, `ToyGame.Sim`, `ToyGame.Sim.Tests`) plus a solution, and the game project's `<Compile Remove="sim/**;tests/**" />` is load-bearing — without it Godot's SDK globs the sim into the game assembly and the boundary dies silently. The ~30 stat, upgrade, research and economy numbers live in C# records and `static readonly` tables inside the sim, so tuning is a rebuild; if live tuning is ever wanted, a `UnitDefResource → UnitDef` mapper added outside the sim costs one file. Damage resolves against sim positions, so any projectile visual must be animated to the sim's reported landing point and flight time rather than to the target's body.
